# Codex Capture

本地 Codex 插件和 macOS 菜单栏助手：按 **Option+S** 进入截图浮层，框选后直接圈选、画箭头或添加文字，旁边可查看前景窗口 AX 信息。点击「完成」后，Luna 随即在后台判断所属项目，同时打开带截图预览的需求输入窗口。识别时显示 loading，完成后显示项目名；点「开始任务」复用识别结果，用项目 ID 和目录新建 chat，原文、原图直接发送并启动任务；添加标注时会另外附上标注图。配置了本机跟进语句后，首轮正常结束且检测到本轮文件变更时才自动发送一次。

这是独立的社区项目，使用 MIT 许可证。界面语言目前为中文。

## 项目结构

当前采用源码仓库与安装脚本分发，尚未发布到 PyPI，也不是单独一个 Python 包。

| 部分 | 技术与位置 | 职责 |
| --- | --- | --- |
| 任务调度和本地服务 | Python 标准库；`plugins/codex-capture/scripts/` | Luna 分类、项目 chat、条件跟进、状态与历史 API |
| macOS 助手 | Swift / AppKit；`plugins/codex-capture/native/` | Option+S、选区与标注浮层、AX 侧栏、描述输入框 |
| 工作台 | React / TypeScript / Voyage；`web/` | 进度、历史、主题和诊断；产物位于 `plugins/codex-capture/web/` |
| Codex 插件 | `plugin.json`、`skills/`、`.agents/plugins/marketplace.json` | 插件安装与 chat 中的任务提交入口 |
| 安装器 | `install.sh` | 编译原生助手、安装插件、注册命令和登录启动 |

Python 运行时不需要安装第三方 Python 依赖；安装和使用已构建的工作台不需要 Node.js。前端开发需要 Node.js 与 pnpm。开发验证见 [TESTING.md](TESTING.md)。

提交成功后，分类、执行和续聊由独立后台进程处理，不需要最初发起请求的 chat 保持运行。插件不配置全局 Stop hook，也不接管其他 chat。

截图入口在输入期间提前分类；直接 `submit --image` 则在提交后分类。菜单栏入口提交后自动打开对应任务的进度工作台，显示阶段、模型进展、工具活动和记录；菜单栏同时显示活跃任务数与当前阶段。初始任务和可选跟进结束、App Server 释放任务写入权后，再打开完整 Codex chat。`--no-open` 跳过打开 Codex chat，任务可能暂时未分组。

## 任务工作台

工作台使用真实 `@yiminlab/voyage` 组件与 theme，参考 Quarry 的工作台布局。入口是菜单栏「任务工作台…」，或：

```sh
code-capture gui
code-capture gui --job JOB_ID
```

- 左侧按项目和状态筛选，中间搜索历史、查看耗时及异常提示，右侧查看选中任务。
- **概览**：截图、原始描述、Luna 的项目判断理由和置信度、模型、工作目录、首轮及预设跟进结果；显示是否发送或跳过跟进及原因。
- **执行过程**：阶段变化、模型进展和工具事件自动更新；历史任务即使没有新版本的阶段日志也能读取。
- **调试**：请求、前景上下文、路由 JSON、事件和后台日志；可下载诊断 JSON，也可从菜单栏打开原始日志目录。
- 可以显式取消运行中的任务；后台结束后才能从工作台打开 Codex chat，避免争用仍在执行的对话。

「流程已结束」只说明首轮与符合条件的跟进已结束，不代表需求已经实现或所有检查都通过。工具失败会独立显示；后台已退出却没有结束记录的任务会标为中断，不会自动重试或补发预设。

工作台仅监听本机回环地址，无外部静态资源。0.4.3 起，在本机数据目录持久保存端口与访问凭据（仅当前用户可读写），重启或升级后继续使用原地址，已有标签页可直接刷新。若端口被其他程序占用，工作台会记录原因并换用空闲端口；从菜单栏「任务工作台…」可重新打开当前地址。服务不负责模型调度，关闭浏览器不会停止任务。事件只展示最近 300 行，日志展示最后 32 KiB，界面与诊断导出会明确标注截断范围；完整记录仍在本机任务目录。

## 运行条件

- macOS、Python 3.10+、Apple Command Line Tools（用于编译 Swift 助手）、已登录的 Codex CLI 0.161.0+。
- 账号可使用 `gpt-6-luna`；正式任务使用工作台默认设置或沿用 Codex 的模型配置，`--model` 可单独指定。
- 安装包包含编译后的网页资源，运行时不需要 Node；开发网页时使用 `web/` 中的 pnpm lockfile 和构建命令。
- 目标项目已保存在 Codex 的本地项目列表中。
- 运行组件依赖当前 CLI 的实验性 App Server 项目接口（包括 `project/list`）。升级后若接口变化，`doctor` 或任务状态会报告失败。

插件复用本机 Codex 登录，调用会消耗相应账户额度。仅支持本机项目；远程主机和云端任务暂不在此版本范围内。

## 安装与更新

克隆仓库后执行（仓库已包含构建后的工作台）：

```sh
git clone https://github.com/yiminspace/codex-capture.git
cd codex-capture
./install.sh
code-capture doctor
code-capture gui
```

也可以解压源码安装包，在解压目录执行 `./install.sh`。保留克隆或解压目录，供本地插件 marketplace 后续更新使用。

安装器通过 Codex CLI 注册 `codex-capture-local` marketplace、安装插件，并检查安装缓存与源码文件一致。它编译本机菜单栏助手并注册用户登录启动，随后启动助手；不会自动截屏、提交任务或授予系统权限。若只需安装而暂不启动，用 `./install.sh --no-launch`。稳定入口包括：

- 终端：`code-capture`（安装到 `~/.local/bin/code-capture`；原 `codex-capture` 命令仍可用）
- Finder 双击：`~/.local/share/codex-capture/Capture.command`
- 菜单栏助手：`~/.local/share/codex-capture/Codex Capture.app`
- 登录启动配置：`~/Library/LaunchAgents/com.yiminlab.codex-capture.plist`

终端的 PATH 需要包含 `~/.local/bin`。`code-capture` 转发到稳定的插件入口，更新插件后继续可用。入口记录安装时 Python 和 Codex 的绝对路径，适用于没有终端 PATH 的启动环境。已有非本插件同名入口不会被覆盖。插件代码实际来自 Codex 安装缓存；运行数据默认保存在 `~/.local/state/codex-capture`，更新代码不会覆盖任务记录。安装器只检查和安装已有网页构建产物，不会自动下载开发依赖。

更新源码后重新运行 `./install.sh`。安装器更新自己管理的助手、入口及登录启动配置；若工作台正在运行，也会将它切换到新安装的网页资源，保留原端口和访问凭据。后台任务独立运行。菜单栏中的退出会正常退出助手，不会立即自动重启；下次登录会启动，也可重新打开 `.app`。已在 Codex CLI 0.161.0 验证同版本重装能够刷新插件缓存；若未来版本未刷新缓存，逐文件校验会报告失败。桌面插件列表的刷新与可发现性需以实际安装结果为准。

助手是本机编译并签名的程序，没有 Developer ID 公证。0.5.1 起，安装器自动创建并持续复用本机专用代码签名身份；原生代码更新时，新旧版本都绑定同一证书和 bundle ID，避免临时签名随构建变化导致系统授权失配。证书、私钥和钥匙串密码保存在 `~/.local/share/codex-capture/signing/`，独立于任务数据和插件缓存；安装和更新不会重新生成身份。安装器只把本工具专用钥匙串加入当前用户的查找列表，保留其他条目和默认钥匙串；私钥不可导出且只授权 `/usr/bin/codesign` 访问。无需添加证书信任，也不修改系统或 TLS 信任。这个本地身份用于本机源码构建，不代表 Apple Developer ID 公证。

原生源码和 Info.plist 未变、文件指纹和固定签名都校验通过时，仍复用原程序。原生更新在替换前验证新版本满足旧版本的签名要求；证书丢失、损坏、过期或不匹配时停止并保留已安装助手，不降级为临时签名。请保留本机签名目录；也可在首次配置时设置 `CODEX_CAPTURE_SIGNING_IDENTITY`，指定已有有效代码签名证书的完整 SHA-1 指纹。后续不能通过改变这个变量静默切换身份。

从旧临时签名升级到固定身份时，安装器只在这次迁移中清理本应用旧的录屏授权记录，之后仍需要用户在 macOS 确认一次新身份的录屏授权。后续普通更新不会重置 TCC 或自动操作权限开关，也无需再初始化证书。插件、网页和助手继续使用独立版本。

若系统设置中的 Codex Capture 屏幕录制开关已开启，助手却仍提示无权限：先退出并重新打开助手。若仍失败，旧版本的临时签名授权可能与当前助手不匹配；在屏幕录制列表移除旧 Codex Capture 项，再用「+」添加 `~/.local/share/codex-capture/Codex Capture.app` 并允许，按系统提示退出并重新打开。插件不会代替用户修改系统授权，也不会重置其他应用的权限。

若重新添加后仍有问题，应先核对助手签名与系统日志，避免反复重装。日志显示已给当前签名授权、之后却仍使用旧校验记录时，可退出助手后，使用 Apple 提供的定向重置命令 `tccutil reset ScreenCapture com.yiminlab.codex-capture` 清除该应用的屏幕录制决定，再由用户重新允许；不使用 `sudo` 或重置全部应用。该命令只撤销旧授权，不会自动授予权限。

0.4.2 的助手在一次运行中最多发起一次系统屏幕录制请求，不再叠加自己的授权弹窗。权限未生效时在菜单与状态中显示原因；在系统设置允许后，按系统提示重新打开助手或使用菜单「刷新权限状态」。

## Editable 开发安装

本机开发可执行 `./install.sh --editable`，让命令、截图助手及插件脚本入口使用当前仓库的 Python 与已构建网页资源。插件仍正常注册到 Codex，运行时选择保存在本机安装记录中；不手工替换插件缓存为软链接。保留仓库目录，移动或删除后需重新安装。

| 修改内容 | 生效方式 |
| --- | --- |
| Python 调度代码 | 下一次命令或新任务直接使用源码；正在执行的任务继续使用已加载代码 |
| Python GUI 后端 | 重新运行 `code-capture gui`；检测源码指纹变化后只重启工作台，复用端口与访问凭据 |
| React / CSS | 在 `web/` 执行 `pnpm build` 后刷新网页，无需重新安装 |
| Swift / Info.plist | 重新运行 `./install.sh --editable`，编译并使用同一固定身份签名 |
| 插件清单或技能说明 | 重新运行安装器以刷新 Codex 插件缓存 |

这是源码直接运行模式；不自动热替换正在执行的任务，也不提供 Swift 热更新。用普通 `./install.sh` 可切回缓存安装模式，任务记录、GUI 地址和本机配置保留。

## 使用

按 **Option+S**，拖选区域，再输入需求并开始。Escape 或取消不会提交任务。已有截图或输入框尚未处理时，重复按键不会再开一份。热键注册使用 macOS 的系统热键接口，不需要「输入监控」权限；若组合被占用，助手状态会报告失败。

输入窗口上方展示本次截图，下方输入需求；项目状态从「正在识别项目…」更新为识别出的项目名。Luna 根据截图、候选项目和可选前景上下文提前判断，此时需求文字仍在输入中。提前点击「开始任务」也可以提交，后台会等待同一次识别结束；不会重复调用 Luna。识别不明确或失败时会显示原因，正式任务尚未开始。取消或关闭输入窗口会取消这次预识别。

首次截图可能需要在「系统设置 → 隐私与安全性 → 屏幕与系统音频录制（或屏幕录制）」允许 **Codex Capture**。这是 macOS 授权，安装器不会代替用户开启。授权后如系统要求重启助手，退出菜单栏助手再重新打开 `.app`。

截取一个区域并输入需求：

```sh
code-capture capture
```

已有图片和描述时：

```sh
code-capture submit \
  --image /absolute/path/screenshot.png \
  --text '请把示例便签的标签移到标题右侧'
```

命令立即返回 job ID，后台处理会继续运行，结束后自动打开完整桌面 chat。首条消息包含原始描述、原始图片和可选标注副本，不追加处理说明或无障碍上下文，不改写用户的文字。已有图片仅复制到任务目录，不重编码。

集成其他输入界面时，可先运行 `prepare --image <路径> [--context-file <路径>]`，读取返回的 `statePath` 展示识别进度；确认后运行 `submit --preparation-id <preparationId> --text=<原文>`，取消时运行 `discard-preparation <preparationId>`。预识别只创建临时只读分类会话；提交后会重新校验项目与目录，并将分类记录复制进任务诊断。

首轮成功完成后，后台对比执行前后的项目文件内容，并结合该轮工具活动判断是否发生修改。只有检测到修改且该轮执行过可能写文件的工具时才原样发送本机配置的跟进语句；仅讨论、未修改、已有脏文件但本轮未改动、无法确认时均跳过。判断依据保存在 `state.json` 的 `followupDecision`，并显示在工作台。

检查以 Git 项目为范围，读取文件内容的指纹，不修改项目；非 Git 目录、超出检查上限且没有可核实的文件变更事件、或其他证据不足的情况会跳过并记录原因。同仓库独立 worktree 的修改需要成功的文件变更事件作证据；只通过 shell 在原工作区之外写文件时，当前版本可能跳过。文件内容对比能排除已有修改，但无法完全区分同一工作区里同时运行的多个写入者。

跟进内容属于个人配置，仓库和安装包不内置任何个人流程或组织策略。全新安装默认不自动跟进。将自己的 UTF-8 语句保存到 `~/.config/codex-capture/followup.txt` 即可启用；如果设置了 `XDG_CONFIG_HOME`，则使用其下的 `codex-capture/followup.txt`。可以用 `CODEX_CAPTURE_FOLLOWUP_FILE` 指定其他本机文件。

文件内容（包括换行与空白）按原样读取，最长 64 KiB，建议将文件权限设为 `600`。默认文件缺失或为空时不跟进；文件读取或解码失败时提交会停止，不会打印其内容。该文件位于源码目录之外，安装和更新不会覆盖它。

命令行 `--followup '你的预设语句'` 优先于工作台设置及本机文件；`--followup ''` 明确禁用当前任务的跟进。`--no-open` 不打开桌面 chat；`--read-only` 用于只读验证且不自动跟进。每个任务会保存提交时的预设快照，后续编辑配置只影响新任务，已有记录不会重发。

查询与取消：

```sh
code-capture status
code-capture status JOB_ID
code-capture cancel JOB_ID
```

安装后的 Codex 新 chat 也可以使用 `capture-task` skill 来提交截图；skill 启动同一个后台入口，不通过发起 chat 再做调度。

再次按 Option+S 可重新截图：新截图成功后更新同一个输入窗口并重新置前，保留已输入的描述与调试面板的展开状态；旧识别会取消，其迟到结果不会覆盖新截图。按 Escape 取消新截图时恢复原窗口与原截图，提交中的任务不能被替换。

截图成功后仍立即在后台识别，与输入需求并行。分类服务复用同一个 app-server 连接，每张截图使用独立的临时会话；闲置两分钟后自动退出，取消或异常的活跃 turn 会释放其连接，后续按需重建。正式执行任务使用独立运行时。

输入窗口仅在弹出时置前，之后按普通窗口切换焦点；「Luna 调试」默认折叠，展开后显示右侧面板，以 Request body / Response body 分别展示分类请求（含提示词、候选项目、前景上下文、图片路径和 schema）、响应及错误，并为 JSON 提供语法高亮。原始图片在窗口上方预览；调试记录保存为 `classification-debug.json`，提交任务后保留副本。

## 默认模型与跟进设置

工作台右上角「默认设置」可修改分类模型、任务模型和跟进预设；任务概览中的「调整默认模型」「编辑跟进预设」也会打开同一设置面板。模型 ID 可输入；分类默认 `gpt-6-luna`，任务模型留空时沿用 Codex 配置。配置保存到本机状态目录的 `settings.json`，不会进入源码或安装包。

分类模型在截图准备时保存快照，改动后对新截图生效。任务模型和跟进预设在提交任务时保存快照，历史记录与已提交任务不重写、不重发。命令行 `--model` / `--followup` 优先于已保存设置；未保存 GUI 跟进设置时继续读取原有本机 `followup.txt`，保留兼容。清空跟进预设可禁用自动跟进。

## 截图标注

macOS 14 及以上：Option+S 进入应用自己的截图浮层，工具栏与 AX 面板立即可见；拖出选区后可直接使用画笔、矩形、圆圈、箭头、文字、六种颜色、粗细、撤销与清空。选择「选区」可移动区域，也可拖动边界调整大小；「完成」或 Enter 才进入需求输入，Escape 取消并恢复旧窗口。AX 面板显示触发时前景窗口的应用、标题、页面 URL、采集状态、节点数量和树内容，可拖动标题移动位置或收起。面板范围是前景窗口，可能大于截图选区；面板和工具栏不会进入输出图片。

浮层使用 ScreenCaptureKit 在内存保存各屏幕快照，只把最终选区写入任务文件。多屏可在任一屏幕单独选区，不跨屏拼接；macOS 13 保留系统选区后的标注入口。输入窗口截图右上角「标注截图…」仍可再次打开编辑器。拖动绘制；文字工具点击位置后输入文字；「使用标注」返回预览，可再次编辑。取消编辑不改变已保存的标注，重新截图成功会清除上一张图的标注。

原图保持原始字节，标注按原始像素尺寸另存 PNG。正式任务首条消息包含原始描述、原图和可选标注图；项目分类继续使用原图与前景上下文。工作台可分别查看原图与标注图。命令行也支持 `submit --annotated-image /absolute/path/marked.png` 配合原图或 `--preparation-id` 提交标注副本。

## 可选的前景无障碍上下文

菜单栏中的无障碍上下文选项默认开启（保留已有的显式关闭设置）。读取还需要在「系统设置 → 隐私与安全性 → 辅助功能」允许 **Codex Capture**；没有授权时截图和描述仍可提交。

助手在按快捷键时记录前景应用，再读取该应用当时聚焦窗口的有限无障碍树，优先读取可见子节点及网页 URL，并跳过窗口边界外的节点，随后才启动截图和输入框。上下文仅作为项目判断的辅助材料交给 Luna，帮助区分浏览器网站、编辑器项目和相似界面，不追加到目标 chat 的首条消息。

- 只读取触发时的一个前景窗口，不扫描所有应用或后台窗口。
- 限制节点数、树深度、文本量和读取时长；不收集密码控件或可编辑输入值。
- 上下文范围可能大于截图选区，会包含同一窗口中的部分界面文字。只有开启此选项并拥有辅助功能授权时才收集。
- 应用未暴露无障碍节点、读取超时或授权缺失时，会记录原因并降级为截图和描述；它不是所有界面的完整 DOM。

若系统开关已打开，但助手仍报告 `accessibilityTrusted: false`，可能是旧授权记录仍绑定旧签名。请从辅助功能列表移除旧 Codex Capture，重新添加当前安装的 `.app` 并开启，然后重新启动助手；系统可能要求 Touch ID 或登录密码认证。只打开应用不会替换旧授权记录。

排查采集时，可调用已安装应用的 `Contents/MacOS/CodexCapture --probe-context <application-bundle-id>`：使用与截图相同的 AX 读取函数输出当前窗口上下文，不请求权限、不截屏、不调用 Luna。只有输出为 `captured` 且含节点/页面 URL，才能确认实际采集成功。 `--probe-screens` 可验证 macOS 14+ 的真实显示器采集，仅输出像素尺寸，不保存全屏图片。

命令行可用 `submit --context-file /absolute/path/context.json` 提交已准备好的上下文。后端校验并裁剪该文件后存入任务目录，作为不可信任务材料处理，不执行其中的指令。

助手状态在 `~/.local/state/codex-capture/hotkey-status.json`。可直接检查：

```sh
~/.local/share/codex-capture/'Codex Capture.app'/Contents/MacOS/CodexCapture --check
```

## 行为边界

- 项目判断不明确或后台失败时，任务停止并记录状态，不会猜测项目继续发起操作。
- 每个任务由独立 worker 启动一个 App Server，保持它运行直到初始任务及可选跟进结束，随后关闭。关闭发起请求的终端或 chat 不会取消任务；机器休眠、重启或进程退出可能中断它。
- 每个任务自动跟进最多尝试发送一次：发送前先持久化状态。崩溃或发送结果不明时不会自动重试，因此可能漏发，但不会为了恢复而重复发送。失败、中断或需要用户参与时不会盲发下一步。
- 截图与原始描述按原样传入目标 chat，不追加说明。项目判断用的辅助上下文只留在分类器和本机诊断记录中。
- 0.4.4 起，正式任务显式选择 Codex 的 Full access 权限档（`:danger-full-access`）与 `never` 审批策略；在发送原文、原图前检查接口返回的实际权限，若未生效则停止并记录原因，不以 Custom 权限继续。分类器与显式 `--read-only` 任务仍保持只读。插件不修改全局权限，已有 chat 不会因插件更新自动改变；首轮及自动跟进使用同一正式 chat 的权限。后续操作由目标 chat 根据用户自己的预设执行；遇到需要人工输入时保留状态并等待用户处理。
- `CODEX_CAPTURE_DATA` 可指定数据目录；`CODEX_CAPTURE_CODEX_BIN` 可指定 Codex 可执行文件。安装记录不保存登录凭据。
- 外部 App Server 执行中持有任务写入权，桌面可能无法加载活动 chat 或显示 `notLoaded`。因此先在本插件工作台显示进度，后台结束并释放写入权后再打开桌面 chat；插件不改写桌面私有状态。

## 验证

安装器检查包内容和入口路径；`doctor` 检查运行条件和项目接口。自动化测试使用虚构任务和合成图片，不携带开发者的真实任务记录。真实账户验收步骤见 [TESTING.md](TESTING.md)，需要在自己的环境核对 Luna 路由、原图与描述、新 chat 的项目归属，以及初始任务和可选跟进结果。

热键助手另行检查编译、无 UI 自检、常驻进程与热键注册状态；这些检查不等同于用户完成屏幕录制授权后的交互截屏验收。实际截图与可选 AX 读取需要在相应系统权限授予后验证。

再次验收时请保留 job ID，检查 `state.json` 中的 `classifierModel`、`nativeProjectId`、`inputTypes`、两个 turn 的完成状态和 `followupAttempts`，并打开桌面 chat 核对图像、对话内容与项目显示。不能把原生项目 ID、深链调用成功或 CLI 安装成功单独当作桌面项目归属已同步的证据。

接口依据：[Codex 插件打包](https://developers.openai.com/plugins/build/plugins)、[App Server](https://learn.chatgpt.com/docs/app-server)。
